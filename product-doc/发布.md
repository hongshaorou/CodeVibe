### 1. VibeCoding “发布”功能

#### **产品名称：** VibeCoding 社区内容发布功能

#### **生成结果：** publish.html

#### **总体目标**
该功能为用户提供一个沉浸式、移动端优先的全屏内容创作界面。用户可以通过主页的浮动按钮进入，完成标题、标签和正文（支持 Markdown 富文本、图片上传、文件导入）的输入，并最终发布。

#### **界面风格与布局 (UI/UX & Style)**
* **设计语言**: 整体遵循 Google Material Design 3 规范，注重清晰的层级、空间感和流畅的交互反馈。
* **承载环境**: 页面中心是一个 `420x850px` 的“手机外壳” (`.mobile-shell`)，所有内容在此区域内，模拟 App 体验。
* **功能入口**:
    * 一个蓝色的圆形浮动操作按钮 (FAB)，位于底部导航栏之上，居中向上偏移。
    * 按钮上有白色的 `+` 图标，并带有自然的阴影效果，暗示其可点击和层级关系。
* **发布面板 (Bottom Sheet)**:
    * 点击 FAB 后，一个白色的面板会从屏幕底部平滑向上滑出，最终覆盖整个手机屏幕。
    * 面板顶部有两个 `1.5rem` 的圆角，呈现 Material Design 中“底部动作条”的经典样式。
    * 面板滑出时，后方的页面会覆盖一层半透明的黑色遮罩，让用户聚焦于创作。
* **面板内部布局**:
    1.  **顶部应用栏 (Top App Bar)**: 固定在面板顶部，包含左侧的“取消”按钮，中间的“发布内容”标题，以及右侧的“发布”按钮。
    2.  **标题输入框**: 紧随顶部栏下方，有清晰的下边框，字体较大，用于输入文章标题。
    3.  **标签区域**: 标题框下方，用于添加和展示标签（Chips）。
    4.  **编辑器区域**: 占据剩余的全部空间，确保创作区域最大化。

#### **核心功能 (Functionality)**
* **编辑器**:
    * 集成功能强大的 `Vditor` Markdown 编辑器。
    * 工具栏经过精简，保留了标题、加粗、引用、代码、列表等常用功能。
* **图片上传**:
    * 工具栏提供“上传图片”按钮。
    * 支持用户一次性选择**多张图片**。
    * 选择后，图片通过 `FileReader` API 转换为 **Base64** 格式，并以 Markdown 形式直接插入编辑器光标所在位置，实现所见即所得的本地预览。
* **文件导入**:
    * 工具栏提供一个自定义的“导入文件”按钮（PDF 图标）。
    * 点击后，模拟调用文件选择器，允许用户选择 `.md` 或 `.pdf` 文件（在原型中通过 `alert` 提示）。
* **标签系统 (Tagging System)**:
    * 提供一个独立的输入框用于添加标签。
    * 用户输入文字后按回车，即可生成一个“小卡片 (Chip)”样式标签。
    * 每个标签旁有关闭按钮 `×`，可以单独移除。
    * 限制最多添加 5 个标签。

#### **核心交互 (Interaction)**
* **打开面板**: 用户点击主页的 `+` FAB -> 面板从 `translateY(100%)` 平滑过渡到 `translateY(0%)`，同时背景遮罩从透明过渡到半透明。
* **关闭面板**: 用户点击“取消”按钮 -> 面板平滑滑回屏幕底部，背景遮罩消失。同时，所有已输入的内容（标题、标签、编辑器内容）将被**清空重置**。
* **发布内容**: 用户点击“发布”按钮 ->
    1.  进行前端校验（标题和内容不能为空）。
    2.  在控制台 (Console) 中打印所有待发布的数据（标题、标签数组、Markdown 内容），模拟API调用。
    3.  弹出一个 `alert` 提示“发布成功！”。
    4.  成功后，自动调用关闭面板的逻辑，清空并收起页面。

### 2. VibeCoding “发布页面” 高保真原型 - 终极版提示词

**角色：** 你是一位名为 CodeVibe 的 AI 产品原型设计师，精通前端技术、UI/UX 设计，尤其擅长 Google Material Design 风格。

**任务：** 请为 VibeCoding 技术社区生成一个**内容发布页面**的高保真、单文件、可交互的 HTML 原型。

**总体要求：**
* **技术栈**：使用纯 HTML、Tailwind CSS（通过 CDN 引入）、原生 JavaScript，并集成 **Vditor** Markdown 编辑器（通过 CDN 引入）。
* **环境**：在页面中央创建一个最大宽度为 `420px`、高度为 `850px` 的 `.mobile-shell` 容器，来模拟手机 App 的视觉效果。所有内容和交互都在此容器内。
* **代码质量**：确保代码完整、无删减、无省略，所有功能必须完整且可用，动画效果流畅。
* **设计规范**：严格遵循 Google Material Design 3 的设计原则，包括字体、颜色、组件样式和间距。

---

### 一、 页面布局与核心交互

1.  **主屏幕 (`.mobile-shell` 内部)**
    * 包含一个静态的顶部状态栏和底部导航栏。
    * 在底部导航栏之上，必须放置一个蓝色的、圆形的**浮动操作按钮 (FAB)**，它作为打开发布功能的**唯一入口**。

2.  **发布面板 (`#publish-overlay` & `#publish-panel`)**
    * 整个发布面板必须放置在 `.mobile-shell` 内部，并使用 `position: absolute` 相对于外壳定位。
    * **初始状态**: 默认完全隐藏在屏幕下方 (`transform: translateY(100%)`)，且 `pointer-events: none`。
    * **触发交互**: 点击 FAB 后：
        * 半透明的黑色背景遮罩层 (`#publish-overlay`) 平滑浮现。
        * 发布面板 (`#publish-panel`) 从底部平滑向上滑入，最终完全占据屏幕 (`transform: translateY(0%)`)。
        * 面板的**顶部必须有两个大的圆角**（如 `rounded-t-2xl`），呈现 "Bottom Sheet" 样式。
    * **关闭交互**: 点击面板内的“取消”按钮，面板和遮罩层以相反的动画收回。

---

### 二、 发布面板 UI 设计 (Material Design 风格)

1.  **顶部应用栏 (Top App Bar)**
    * 固定在面板顶部，有底部边框。
    * **左侧**: “取消”按钮，必须是**文字按钮**样式（无背景，品牌蓝色文本）。
    * **中间**: “发布内容”标题，字体加粗。
    * **右侧**: “发布”按钮，必须是**填充按钮**样式（品牌蓝色背景，白色文字，胶囊形状）。

2.  **内容输入区 (垂直Flex布局)**
    * **标题输入框 (`<input id="post-title">`)**:
        * 位于顶部栏下方，有清晰的下边框线。
        * 字体尺寸较大（如 `text-2xl`），`font-weight` 为 `medium`。
        * 获得焦点时，下边框线颜色变为品牌蓝色。
    * **标签系统区域**:
        * 包含一个用于展示已添加标签的容器 (`#tag-container`) 和一个输入框 (`#tag-input`)。
        * 已添加的标签必须是 **Chip (小卡片)** 样式：浅灰色背景，圆角，并包含一个可点击的 `×` 来移除标签。
    * **编辑器容器 (`<div id="markdown-editor">`)**:
        * **必须占据所有剩余的垂直空间** (`flex-grow: 1`)，确保内容创作区最大化。

---

### 三、 Vditor 编辑器集成与功能

1.  **Vditor 初始化**:
    * 编辑器高度需设置为 `100%` 以填充其容器。
    * 开启打字机模式 (`typewriterMode: true`)。

2.  **Vditor 工具栏配置**:
    * 必须包含以下标准按钮: `headings`, `bold`, `italic`, `strike`, `quote`, `code`, `inline-code`, `list`, `ordered-list`, `check`, `undo`, `redo`。
    * **必须包含标准的 `upload` 按钮**，用于图片上传。
    * **必须在工具栏末尾添加一个自定义的“导入文件”按钮**:
        * **图标**: 使用内联 SVG 实现一个 PDF 或文档的图标。
        * **功能**: 点击后，触发一个隐藏的 `<input type="file">`，模拟文件选择。

3.  **图片上传功能 (`upload` 配置项)**:
    * 必须允许用户**多选图片** (`multiple: true`)。
    * 在 `handler` 回调函数中，遍历所有选择的文件，使用 `FileReader` API 将每个文件转换为 **Base64** 数据。
    * 将转换后的 Base64 数据以 `![alt](data:image/...)` 的 Markdown 格式插入到编辑器中。

### 四、 JavaScript 交互逻辑

1.  **打开/关闭逻辑**:
    * 精确实现 `transform` 和 `backgroundColor` 的平滑过渡动画。
    * 关闭面板时，**必须清空**标题、标签数组、Vditor 编辑器中的所有内容。

2.  **标签系统逻辑**:
    * 在标签输入框中按回车，添加一个新标签到数组并重新渲染 Chip 列表。
    * 实现**最多 5 个标签**的限制。
    * 实现点击 Chip 上的 `×` 按钮，从数组中删除对应标签并重新渲染。

3.  **发布逻辑**:
    * 点击“发布”按钮，获取标题、标签数组和 Vditor 的 Markdown 内容 (`vditor.getValue()`)。
    * 校验标题和内容不为空。
    * 将所有数据 `console.log` 出来。
    * `alert("发布成功！...")`。
    * 调用关闭面板的函数。
