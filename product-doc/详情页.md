### VibeCoding “内容详情页”

**角色：** 你是一位名为 CodeVibe 的 AI 产品原型设计师，精通前端技术和用户体验设计。

**任务：** 请为 VibeCoding 技术社区生成一个**内容详情页**的高保真、单文件、可交互的 HTML 原型，当前目录文件在名为："detail.html"

**总体要求：**
* **技术栈**：使用纯 HTML、Tailwind CSS（通过 CDN 引入）和原生 JavaScript（无需任何框架）。
* **环境**：在页面中央创建一个最大宽度为 420px、高度为 850px 的 `.mobile-shell` 容器，来模拟手机 App 的视觉效果。所有内容和交互都在此容器内。
* **代码质量**：确保代码完整、无删减、无省略，所有功能（尤其是 JavaScript 交互）必须完整且可用。

---

### 一、 页面布局与样式 (Layout & Styles)

1.  **顶部导航栏 (`<header>`)**
    * **样式**：固定在页面顶部，白色背景，有底部边框。
    * **功能**：左侧包含一个 SVG 格式的“返回”箭头图标和“返回”文字，作为返回上一页的入口。

2.  **内容滚动区 (`<main>`)**
    * **布局**：占据导航栏和底部操作栏之间的所有剩余空间，并且是页面唯一可垂直滚动的部分。
    * **内边距**：为内容提供合适的 `padding`。

3.  **底部固定操作栏 (`<footer>`)**
    * **样式**：固定在页面底部，白色背景，有顶部边框，`z-index` 需设置为 `20`。
    * **内容（左侧）**：一个圆角的、浅灰色背景的静态输入框提示，文案为“说说你的看法...”，作为评论功能的**主要触发器**。
    * **内容（右侧）**：包含“点赞”（带计数）、“收藏”和“分享”三个操作按钮，使用 SVG 图标。

---

### 二、 核心内容展示 (Content Display)

1.  **文章主体**
    * **标题**：使用 `<h1>` 标签，字体加粗，尺寸醒目。
    * **作者信息**：在标题下方，显示作者的圆形头像、昵称和发布日期。
    * **Markdown 内容渲染**：正文部分必须模拟完整的 Markdown 渲染效果，包括：
        * 段落 (`<p>`)
        * 引用 (`<blockquote>`)，带左边框样式。
        * 无序列表 (`<ul>`)
        * 图片 (`<img>`)
        * **代码块 (`<pre><code>`)**：必须使用 `highlight.js` 库（通过 CDN 引入）进行语法高亮，并应用 `atom-one-dark` 主题。
    * **标签**：在文章末尾，以圆角胶囊样式展示相关技术标签。

2.  **评论区**
    * **列表**：完整展示所有评论，而非预览。每条评论包含用户头像、昵称、评论时间和评论内容。
    * **“我的评论”**：在列表中设定一条为当前用户的评论，其昵称旁需有特殊标识（如“You (我)”），并在这条评论下增加一个红色的**“删除”**按钮。
    * **回复按钮**：每条评论下方都有一个“回复”按钮，作为打开评论面板的**次要触发器**。

---

### 三、 交互式评论/回复面板 (Interactive Comment Panel)

这是页面的核心交互，必须精确实现：

1.  **触发与动画**
    * 点击底部操作栏的“说说你的看法...”或任何“回复”按钮，都会触发此面板。
    * 面板从屏幕底部平滑向上滑出，初始高度为 `60vh`（屏幕高度的60%）。
    * 同时，页面其他部分被一个半透明的黑色遮罩层覆盖。点击遮罩层可以关闭面板。

2.  **样式与层级**
    * 面板必须使用 `position: fixed` 和一个极高的 `z-index` (如 `1000`)，以确保它**能完全覆盖**页面底部的固定操作栏。
    * 面板顶部为圆角。

3.  **全屏模式**
    * 面板头部有一个“全屏”切换图标。
    * 点击后，面板高度平滑过渡到 `100dvh`，充满整个屏幕，同时图标切换为“收起”状态。再次点击则返回 `60vh`。
    * **关键布局**：面板内部必须使用 Flexbox 布局，确保头部 `flex-shrink: 0`（不收缩），内容区 `flex-grow: 1` 和 `overflow-y: auto`（占据剩余空间并内部滚动）。这是为了**防止在移动端浏览器弹出虚拟键盘时，面板头部的“取消”和“发布”按钮被挤出可视区域**。

4.  **Markdown 编辑器 (Toast UI Editor)**
    * 面板内容区集成 **Toast UI Editor**（通过 CDN 引入）。
    * **配置**：默认模式为 `wysiwyg` (所见即所得)，工具栏仅保留常用项：`heading`, `bold`, `italic`, `quote`, `code`, `codeblock`。
    * **多图上传功能**：
        * 在工具栏中创建一个**自定义按钮组**，包含“拍照”和“从图库选择”两个功能。
        * **图标**：这两个按钮的图标必须使用**内联 SVG** 的方式实现，以确保在任何环境下都能正确显示，**禁止使用外部字体库**。
        * **功能模拟**：
            * 点击“拍照”按钮，触发一个 `capture="camera"` 的文件输入框。
            * 点击“图库”按钮，触发一个 `multiple` 的文件输入框。
            * 用户选择图片后（支持多选），使用 JavaScript 的 `FileReader` API 将图片转换为 **Base64** 数据。
            * 将带有 Base64 数据的 Markdown 图片语法 `![alt](data:image/...)` 插入到编辑器的光标位置，实现本地预览。

---

### 四、 核心功能交互逻辑 (Core Functional Logic)

1.  **发布评论**
    * 点击评论面板头部的“发布”按钮。
    * **功能模拟**：
        1.  使用 `editor.getHTML()` 获取编辑器的内容。
        2.  在页面的评论列表顶部，动态创建一个新的评论 `div` 并插入获取到的 HTML 内容。
        3.  使用 `editor.setMarkdown('')` 清空编辑器。
        4.  调用关闭函数，收回评论面板。
        5.  弹出一个 `alert` 提示“评论发布成功！”。

2.  **删除评论**
    * 点击“我的评论”下方的“删除”按钮。
    * 弹出一个 `confirm` 对话框进行确认。
    * 确认后，该条评论元素有一个平滑的淡出动画，然后从 DOM 中移除。
